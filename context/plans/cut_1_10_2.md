## Why there is a 1.10.2 at all

The 2026-09-21 architecture work touches `zwiper`, so a client build is spent
whether or not anything user-facing rides along. That makes it worth pairing
with the small client fixes that are already specced rather than shipping a
release nobody can see.

## Already done (internal, no changelog line)

Nothing here is user-visible; it belongs in the progress log, not the changelog.

- The `zerver` feature flag is gone: 598 gates to zero, and `zwiper` no longer
  depends on the server crate at all.
- Passwords are unprintable. `Password` and the new `Secret` redact `Debug`
  and `Display`; five auth request types and eight contract fields adopted
  `Secret`.
- API paths are constants, and the integration suite calls them, so a wrong
  path fails a test instead of shipping a 404.
- Every call is an `Endpoint`; client transport collapsed to one function.

   workspace, workspace tests, and the client crates warning-free.
2. Bump `version` in the workspace `Cargo.toml` to 1.10.2.
3. Move the changelog block from `UPCOMING` to `RELEASES` with the ship date.
4. iOS: [`../operations/ios/app-store/submission/`](../operations/ios/app-store/submission/) build then publish.
   Standing gotchas: latest Xcode, wipe the cargo iOS cache after any Xcode
   update, Info.plist version patch, Transporter (never altool).
5. Android: [`../operations/android/play-store/submission/`](../operations/android/play-store/submission/).
   `zcripts/android/patch_bundle.sh` is not optional; skipping it silently
   reships the manifest bugs. Run the four verification greps.

   "Commander"; use "leader".
