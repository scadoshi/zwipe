# 419. Guides live only on zwipe.net

State: closed | Owner: halo | PR: pushed to release in phases | Build seen: ea76d3002

## Report
From Scotty, through the composer: guide content moves to one shared place that zwipe.net and the web app both render from. The web app gets public guide routes (signed in or out) with `rel=canonical` to zwipe.net. Every guide link inside the web app opens the web app's guide, and the phone app's guide links open app.zwipe.net's guide in the browser. The plan is `context/plans/shared_guides.md`.

## Fix
halo, in phases:
1. **The guides to zwipe-core:** `content::guides` holds `Guide`, `Block`, `GUIDES`, `image_size`, `screenshots` and `find`. zite renders from it with no visible change, and its build script checks the sitemap's slugs against core's file.
2. **The screenshots to one public path at zwipe.net:** the 22 files move from `zite/assets/guides/` to `zite/public/guide-images/` (served as-is at `https://zwipe.net/guide-images/<slug>/<file>`). zwipe-core's `image_url` builds that address from `site::WEB_BASE`, and zite's pages load it. zite's `asset!` registry is gone. Its tests check that every screenshot is in `public/guide-images/` and matches its frame's size. Not checked live: port 8080, where a debug build points, was held by another session's dx. Surfer checks after deploy.
3. **The rendering to components,** in two steps. (a) zwipe-ui `guides` holds what the pages show: a line's runs (`tokens`, `prose`), the index's `hits` (search and tag), `TAGS` and `tag_color_class`, `heading_anchor`, `swipe_class`, a guide's `shots` and `related`. components draws them: `GuideIndex` (heading, filter row, cards), `GuideArticle` (article, "In the app" gallery, related guides) and `GuideMissing`, each taking the host's `href` for a guide's path so a link stays on its own site. `MediaFrame` moves to components with them. zwipe.net keeps its page shell and JSON-LD; its index, two guides and the missing page render the same HTML through the router as before, byte for byte. (b) The CSS they need moves to components' `guides.css` (`GUIDES_CSS`): the card grid, the media frame, the gallery chrome, the guide rules and the screenshot layout, out of zwipe.net's `style.css`. The frame's ready script moves from zwipe.net's `index.html` to `MEDIA_FRAME_JS`. zwipe.net loads both, the sheet after `style.css` and before the kit's `SITE_CSS`, where the rules sat. The link, ink and status-color gates and the reading-measure check scan the new sheet. Checked on two SSG builds, release and this one, in headless Chrome at 1400 and 390: every element's computed style and box on home, About, Community, Contribute, the guides index and three guides is the same, apart from opacity and transform caught mid-entrance on home and Community.
4. **Scotty's extras, in the shared components:** the arrow keys and `h` and `l` (lowercase, since Shift+H opens the shortcuts) step a guide's gallery while focus is in it or on nothing (components' `use_scoped_keys`); a guide's tag chips link to the index filtered to that tag; the index keeps its search and tag in the address's query (`?tag=Deck+stats&q=mana`, zwipe-ui's `IndexFilter`), opening on the one there and replacing it in place as it changes, so Back from a guide and a shared link show the same list. The share-your-deck guide says the link opens at app.zwipe.net; its second screenshot is Surfer's reshoot of an app.zwipe.net share page, under a new name (`02-shared-page-app.webp`) since the address isn't hashed.
5. **The web app's guide routes and the link bases:** zwiper-web serves `/guides` and `/guides/<slug>` in `OpenFrame`, open to everyone (`is_open`), with the signed-in nav or the public one, and no menu section; a guide's back arrow goes to the index (the screen before it when there is one, so the filter comes back). Each page puts `rel=canonical` on its zwipe.net twin (`site::WEB_BASE`). The app links `11-guides.css`, the kit's gallery base (the Gallery part of `SITE_CSS`) and `GUIDES_CSS`, and runs `MEDIA_FRAME_JS`; `GUIDES_CSS` gains guide-scoped rules for the index heading, the article's panel and the blocks' spacing at zwipe.net's values, so the pieces stand without zwipe.net's sheet. `hint::guide::url` takes a `GuideBase`: the web app's hints link its own `/guides/<slug>` (a new tab, as every dialog link opens, so the page under the dialog keeps its state) and the phone app's `https://app.zwipe.net/guides/<slug>`. Checked signed out in the web app at 1400 and 390 (headless Chrome over the DevTools protocol): the index with 22 cards, a guide with its gallery and loaded screenshot marked ready, the canonical link.
6. **Surfer's web differences:** the guide screens keep one `rel=canonical` in the head themselves (set on mount, updated per guide, taken out on unmount), since a `document::Link` outlives its screen in the app, so moving between guides leaves one (checked: index, guide, related guide, Back twice, one link each, the right address). The swipe legend's colors (`.swipe-add` and the rest) move from zwipe.net's sheet to `GUIDES_CSS`, with the status-color allowance, and the guide's bullet and swipe lists take zwipe.net's 1.25rem indent and ink. The index's heading drops the `page-header` class, which the app styles as its own screen header (narrow and centered), so it runs the page's width as on zwipe.net.

Surfer passed it live on app.zwipe.net and zwipe.net (the guide pages, the extras, the web app's guide routes and Surfer's three differences), through the composer, 2026-11-12.
